# xaft v0.1

**xaft** is an autonomous coding agent CLI. Give it a task in plain English, it reads, edits, and tests your code.

---

## Prerequisites

| Requirement | Version |
|---|---|
| Rust | ≥ 1.86 |
| `just` | any |
| An LLM API key | Anthropic or OpenAI-compatible |

---

## Build

```bash
# From the xaft workspace root
cd /root/rust_projects/xaft

# Build the binary
CARGO_TARGET_DIR=/root/rust_projects/injectable-target-local cargo build --release -p xaft

# Or via just (if Justfile is present)
just build
```

The binary lands at:
```
/root/rust_projects/injectable-target-local/release/xaft
```

Add it to your PATH or use the full path below.

## Configuration

### Precedence (highest wins)

xaft merges configuration from six sources in order:

| # | Source | Location |
|---|--------|----------|
| 1 | **CLI flags** | `xaft run --model … --provider …` |
| 2 | **Environment variables** | `XAFT_*` vars (see below) |
| 3 | **Session overrides** | `~/.xaft/sessions/<id>/config.toml` |
| 4 | **Project config** | `.xaft.toml` found by walking up from cwd |
| 5 | **User global config** | `~/.config/xaft/xaft.toml` |
| 6 | **Built-in defaults** | Always present |

The project config (`.xaft.toml`) lives at the root of your project — put it in
the same directory you run `xaft` from, or anywhere up the directory tree.
It is picked up automatically; no flag needed.

---

### Config file format

All config files use TOML. A full annotated example:

```toml
# ── Core ──────────────────────────────────────────────────────────────────────
[core]
log_level = "info"          # trace | debug | info | warn | error
data_dir  = "~/.xaft"       # sessions, debug logs
telemetry = false

# ── Providers ─────────────────────────────────────────────────────────────────
# Each named provider block can be referenced by agent presets.

[provider.anthropic]
type        = "anthropic"
api_key_env = "ANTHROPIC_API_KEY"   # preferred: read key from env var
# api_key   = "sk-ant-…"           # or inline (not recommended)
base_url    = "https://api.anthropic.com"
max_retries = 3
timeout_secs = 120

[provider.openai]
type        = "openai"
api_key_env = "OPENAI_API_KEY"
base_url    = "https://api.openai.com/v1"

[provider.local]
type     = "openai-compatible"
base_url = "http://localhost:11434/v1"
api_key  = "ollama"

# ── Agent presets ─────────────────────────────────────────────────────────────
# "default" is used unless overridden by --agent.

[agent.default]
provider      = "anthropic"
model         = "claude-3-5-sonnet-20241022"
max_turns     = 25
temperature   = 1.0
# system_prompt = ""          # empty = use built-in coder prompt
# allowed_tools = ["*"]       # glob patterns; "*" = all
# denied_tools  = []

[agent.fast]
provider    = "openai"
model       = "gpt-4o-mini"
max_turns   = 10
temperature = 0.5

# ── Guardrails ────────────────────────────────────────────────────────────────
[guardrail]
file_destruction = true    # block destructive operations
secret_leakage   = true    # redact secrets from tool outputs
cost_limit       = false   # enable per-session spend cap
command_approval = false   # require Y/N before shell commands

[guardrail.cost_limit_config]
max_spend             = 1.00   # USD per session
max_tokens_per_request = 65536
warn_at_percent       = 80

# ── TUI ───────────────────────────────────────────────────────────────────────
[tui]
theme      = "dark"     # dark | light | solarized
mouse      = true
timestamps = false

[tui.layout]
conversation_width = 70   # % of terminal width
sidebar_width      = 30
```

### Environment variable overrides

Env vars override the config file for any key. They are applied after the
project config, before CLI flags.

| Variable | Equivalent config key |
|---|---|
| `XAFT_MODEL` | `agent.default.model` |
| `XAFT_PROVIDER` | `agent.default.provider` |
| `XAFT_CORE__LOG_LEVEL` | `core.log_level` |
| `XAFT_CORE__DATA_DIR` | `core.data_dir` |
| `XAFT_CORE__TELEMETRY` | `core.telemetry` |
| `XAFT_AGENT_DEFAULT__MODEL` | `agent.default.model` |
| `XAFT_AGENT_DEFAULT__MAX_TURNS` | `agent.default.max_turns` |
| `XAFT_AGENT_DEFAULT__TEMPERATURE` | `agent.default.temperature` |
| `XAFT_PROVIDER_ANTHROPIC__API_KEY` | `provider.anthropic.api_key` |
| `XAFT_PROVIDER_OPENAI__API_KEY` | `provider.openai.api_key` |
| `XAFT_ANTHROPIC_API_KEY` | shorthand for `provider.anthropic.api_key` |
| `XAFT_OPENAI_API_KEY` | shorthand for `provider.openai.api_key` |
| `ANTHROPIC_API_KEY` | universal fallback for Anthropic providers |
| `OPENAI_API_KEY` | universal fallback for OpenAI providers |

Pattern: `XAFT_PROVIDER_<NAME>__<KEY>` and `XAFT_AGENT_<NAME>__<KEY>` work
for any provider or agent name (uppercase, hyphens → underscores).

---

### Debug log

When the TUI is active, tracing output is redirected from stderr to:

```
~/.xaft/debug-<pid>.log
```

Override the directory with `XAFT_CORE__DATA_DIR=/custom/path` or
`[core] data_dir = "/custom/path"` in any config file.

## Usage

```
xaft [OPTIONS] <COMMAND>

Commands:
  run          Run a task in the current directory
  config       Manage configuration
  session      List or resume sessions
  completions  Generate shell completions
  version      Show version info

Options:
  -h, --help     Print help
  -V, --version  Print version
```

### Run a task

```bash
# Navigate to your project
cd /path/to/my-project

# Run a coding task
xaft run "Add type annotations to all functions in src/"

# Dry-run: show what xaft would do without making changes
xaft run --dry-run "Refactor the auth module to use async/await"

# Headless mode (no interactive output, just logs)
xaft run --headless "Fix the failing tests in tests/integration/"

# Limit cost
xaft run --max-cost 0.50 "Rewrite the README"
```

### Session management

Every `xaft run` creates a session. Sessions persist in `~/.xaft/sessions/`.

```bash
# List sessions for the current directory
xaft session list

# Resume a suspended session
xaft session resume <session-id>
```

## Run xaft on the bundled example

The `xaft-examples/python-password-generator/` directory contains a Python
password generator with eight documented bugs. It's a great first target.

```bash
cd /root/rust_projects/xaft/xaft-examples/python-password-generator

# Inspect what's there
ls -la

# Fix the cryptographic security bug
xaft run "Replace all uses of random.choice with secrets.choice for cryptographic security"

# The agent will:
# 1. Read password_generator.py
# 2. Identify all random.choice calls
# 3. Replace them with secrets.choice
# 4. Verify the change is self-consistent
# 5. Commit the result (if in a git repo)
```

More example prompts:

```bash
# Fix all documented bugs
xaft run "Fix all the bugs documented in the module docstring of password_generator.py"

# Add CLI interface
xaft run "Add a proper argparse CLI to password_generator.py with --length, --no-upper, --no-digits, --no-special, --count flags"

# Add type hints
xaft run "Add PEP 484 type annotations to all functions in password_generator.py"

# Improve tests
xaft run "Improve the test suite in tests/test_password_generator.py to achieve full branch coverage"
```

## Architecture overview

```
xaft (binary)
 └── XaftRuntime::bootstrap(config)
       ├── ProviderFactory → CostedProvider(FallbackProvider(Anthropic/OpenAI))
       ├── FsWorkspaceStore    — reads/writes files in working_dir
       ├── GitRepo             — optional branch isolation (auto-commit on success)
       ├── ToolRegistry
       │     ├── read_file, write_file, edit_file, list_files, grep
       │     ├── bash_exec
       │     └── git_status, git_diff, git_stage, git_commit, git_log
       ├── Orchestrator
       │     ├── Planner (OneShotPlanner → IterativeRefinementPlanner)
       │     ├── Coder   (SubagentTool<EditSummary>)
       │     └── QA ↔ Fixer (HandoffOrchestrator — cycles until APPROVED)
       └── SignalBus → xaft-tui (when interactive)
```

### Key crates

| Crate | Purpose |
|---|---|
| `xaft` | Binary entry point |
| `xaft-cli` | Argument parsing, dispatch, tracing init |
| `xaft-config` | Config loading (6-layer precedence) |
| `xaft-runtime` | `XaftRuntime`, orchestrator, session store |
| `xaft-agent` | `XaftAgent`, lifecycle hooks, signals |
| `xaft-tools` | File/git/shell tool implementations |
| `xaft-tui` | Ratatui TUI — streaming pane, approval dialog |
| `agtrs-runtime` | Agent executor, LLM abstraction, SignalBus |
| `agtrs-anthropic` | Anthropic Claude provider |
| `agtrs-openai` | OpenAI / compatible provider |
| `agtrs-git` | Git worktree manager |
| `agtrs-shell` | Sandboxed shell executor |
| `agtrs-workspace` | Transactional file editor |

## Limitations in v0.1

- Sessions are not resumable across crashes yet (schema stabilisation in progress)
- No HTTP/websocket streaming API
- TUI log panel shows events from SignalBus only — no streaming LLM text between turns
  (agent output appears when each turn completes, not character-by-character)
- Parallel tool calls disabled for models that generate malformed parallel calls
  (e.g. poolside/laguna-m.1); sequential is safe and correct
